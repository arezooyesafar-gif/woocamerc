# ماژول «CSS استفاده‌شده هر صفحه» (`css_usage`)

جایگزین محلی «Remove Unused CSS» راکت. سرویس ابری راکت روی سایت کار نمی‌کند (نسخه نصب‌شده درخواست‌ها را به `wpsaas.gpltimes.com` می‌فرستد و هیچ صفحه‌ای `completed` نشد)، پس این کار روی هاست خودتان انجام می‌شود.

## چه می‌کند
1. برای بازدید مهمان (در صفحات کش‌شده فقط یک بار، هنگام ساخت کش راکت؛ در صفحات بدون کش مثل نتایج جستجو در هر بار)، برای هر فایل CSS داخلی صفحه فقط قوانینی را نگه می‌دارد که کلاس/آیدی/تگ آن‌ها در HTML صفحه یا در فایل‌های JS همان صفحه وجود دارد.
2. این قوانین را دقیقاً در همان جای تگ `<link>` به‌صورت `<style>` قرار می‌دهد (ترتیب CSS عوض نمی‌شود).
3. خود فایل کامل را هم در همان جا با `media="print"` و `onload` نگه می‌دارد. از نسخه 1.5.0 (گزینه «بعد از رویداد load»، پیش‌فرض روشن) آدرس این فایل‌ها در صفحه کش‌شده راکت به `data-tarh99-href` تبدیل می‌شود و یک اسکریپت کوچک بعد از رویداد `load` آن‌ها را دانلود می‌کند تا روی اینترنت کند با تصویر LCP و فونت‌ها رقابت نکنند (موقعیت تگ و ترتیب CSS تغییر نمی‌کند؛ بدون جاوااسکریپت از `<noscript>` لود می‌شوند) تا بعد از نمایش صفحه، بدون مسدود کردن، اعمال شود. یعنی هر چیزی که بعداً با کلیک یا جاوااسکریپت ظاهر می‌شود هم قوانین کاملش را دارد.
4. فایل‌های بیرونی (Google Fonts)، `print.css` و فایل‌های بزرگ‌تر از ۱.۵ مگابایت دست نمی‌خورند.

نتیجه تست روی نسخه محلی (قالب پوشه + ووکامرس): CSS مسدودکننده هر صفحه از ~۷۱۶KB (gzip ‏~۱۰۶KB) به ~۱۷۰KB (gzip ‏~۳۰KB) رسید؛ اسکرین‌شات موبایل و دسکتاپ صفحه اصلی، دسته و محصول (حتی با مسدود کردن کامل فایل‌های اصلی) پیکسل‌به‌پیکسل یکسان بود و استایل محاسبه‌شده همه المان‌ها برابر بود. حالت تاریک، مودال ورود، فیلتر موبایل و tooltip هم یکسان بودند. زمان پردازش سرور هنگام ساخت کش: ~۵۰ میلی‌ثانیه (اولین بار بعد از تغییر فایل‌ها ~۳۰۰ میلی‌ثانیه).

## روشن کردن (مرحله‌ای)
1. پیشخوان ← سرعت طرح۹۹ ← تب ماژول‌ها ← «CSS استفاده‌شده هر صفحه» **خاموش** است. تا مرحله ۳ روشنش نکنید.
2. **پیش‌نمایش (فقط شما می‌بینید):** با حساب مدیر، صفحه اصلی را در یک تب با آدرس `https://tarh99.com/?tarh99_css=preview` و در تب دیگر `https://tarh99.com/` باز کنید. موبایل (DevTools ← حالت موبایل) و دسکتاپ را مقایسه کنید: هدر، منو، اسلایدرها، فونت، حالت تاریک، جستجو، فوتر. همین کار را برای یک دسته (`/product-category/.../?tarh99_css=preview`) و یک محصول انجام دهید.
   - در سورس صفحه پیش‌نمایش (Ctrl+U)، آخرین خط چیزی شبیه `<!-- tarh99 css_usage: 18 files, 900 KB -> 220 KB, 60 ms -->` است.
3. اگر یکسان بود: ماژول را روشن کنید، «محدوده اجرا» را اول فقط `front` بگذارید ← ذخیره (کش راکت خودکار پاک می‌شود).
4. صفحه اصلی را در پنجره ناشناس باز کنید، سورس (Ctrl+U) ← جستجوی `data-tarh99-used` باید پیدا شود. PageSpeed موبایل بگیرید.
5. بعد از یکی دو روز بدون مشکل، محدوده را به مقدار پیش‌فرض `all, !cart, !checkout, !account` برگردانید.

## اگر جایی فرق داشت
- **سریع‌ترین راه:** ماژول را خاموش کنید و ذخیره کنید (کش پاک می‌شود و همه چیز مثل قبل است).
- برای مقایسه روی سایت زنده بعد از روشن کردن: مدیر لاگین‌شده همیشه نسخه اصلی را می‌بیند؛ نسخه بهینه را با `?tarh99_css=preview` ببینید.
- اگر یک بخش خاص (مثلاً یک ویجت) بعد از کلیک بدون استایل بود، بخشی از کلاس آن را در «قوانینی که همیشه نگه داشته شوند» اضافه کنید.
- اگر یک فایل CSS خاص مشکل داشت، بخشی از آدرسش را در «فایل‌های CSS که دست نخورند» بنویسید.

## نکات
- برای کاربران لاگین‌شده، سبد، تسویه و حساب کاربری اجرا نمی‌شود.
- نتیجه پردازش هر فایل CSS در `wp-content/cache/tarh99-perf/css_usage/` (فشرده) نگه داشته می‌شود و با تغییر فایل (مثلاً ذخیره صفحه در المنتور) خودکار دوباره ساخته می‌شود.
- با «LazyLoad تصاویر پس‌زمینه CSS» راکت سازگار است (راکت هم فایل‌ها و هم استایل‌های داخلی را پردازش می‌کند).
- «بهینه‌سازی تحویل CSS» راکت باید **خاموش** بماند.
