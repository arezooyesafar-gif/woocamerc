# پیشنهادهای .htaccess (مرحله ۴)

## وضعیت فعلی
- بلوک `# BEGIN WP Rocket` فشرده‌سازی gzip (mod_deflate)، Expires و حذف ETag را مدیریت می‌کند ✅
- **بلوک rewrite کش WP Rocket وجود ندارد** (بخش `<IfModule mod_rewrite.c>` که فایل HTML کش‌شده را مستقیم و بدون PHP سرو می‌کند). یعنی هر صفحه کش‌شده هم از مسیر PHP (`advanced-cache.php`) سرو می‌شود.
  - اقدام: در WP Rocket یک‌بار «ذخیره تغییرات» بزنید تا `.htaccess` بازنویسی شود، سپس بررسی کنید بلوک `RewriteCond %{HTTP_COOKIE} !(wordpress_logged_in_...` اضافه شده یا نه. اگر اضافه نشد، از پشتیبانی هاست بپرسید وب‌سرور Apache است یا LiteSpeed و آیا `mod_rewrite` محدود شده است.
- قوانین AIOS (فایروال 5G) و قانون PHP هاست (`ea-php81`).

## قوانین پیشنهادی
فایل آماده: [`docs/htaccess-additions.txt`](htaccess-additions.txt)

**محل قرار دادن:** بالای فایل `.htaccess` در ریشه سایت، **قبل از** `# BEGIN WP Rocket`. چون بیرون از نشانگرهای WP Rocket/AIOS/WordPress است، با ذخیره تنظیمات آن افزونه‌ها پاک نمی‌شود و با آن‌ها تداخلی ندارد (هیچ قانونی از راکت تکرار یا بازنویسی نشده است).

| قانون | کار | تداخل |
|---|---|---|
| Brotli | اگر ماژول `mod_brotli` روی سرور باشد، CSS/JS/HTML/SVG را ۱۵–۲۰٪ کوچک‌تر از gzip می‌فرستد. چون راکت `SetOutputFilter DEFLATE` می‌گذارد، برای مرورگرهایی که br را قبول می‌کنند gzip غیرفعال می‌شود تا Brotli اعمال شود. اگر ماژول نباشد کل بلوک نادیده گرفته می‌شود. | ندارد؛ مرورگرهای بدون پشتیبانی همان gzip راکت را می‌گیرند |
| کش یک‌ساله فونت‌ها با `immutable` | فونت‌های woff2 قالب هر بار دوباره اعتبارسنجی نمی‌شوند | راکت برای فونت ۴ ماه می‌گذارد؛ این قانون فقط هدر Cache-Control را برای فونت‌ها کامل‌تر می‌کند |
| مسدودکردن پوشه‌های اضافی `plugins/Addons`، `Help`، `Plugin`، `Yoast`، `__MACOSX`، `2- Documentation` | تا زمان حذف این پوشه‌ها، ۲۶۴ فایل PHP آن‌ها از بیرون قابل اجرا نباشد | ندارد |
| مسدودکردن اجرای PHP در `uploads` و پوشه کش این افزونه | جلوگیری از اجرای فایل PHP آپلودشده | ندارد (اگر AIOS همین را فعال کرده باشد تکراری ولی بی‌ضرر است) |
| `wflogs` | بستن دسترسی به لاگ‌های باقی‌مانده Wordfence | ندارد |

## تست انجام‌شده
این بلوک همراه با کل `.htaccess` فعلی سایت روی Apache 2.4.58 (با ماژول‌های headers، alias، brotli، deflate، expires) تست شد: هیچ خطای ۵۰۰ نداد، پوشه‌های اضافی و PHP داخل uploads خطای 403 دادند، فایل‌های عادی 200 ماندند، CSS برای مرورگر دارای br با Brotli و برای بقیه با gzip فرستاده شد و فونت‌ها هدر `immutable` گرفتند.

## بعد از افزودن
1. چند صفحه (اصلی، محصول، سبد، پیشخوان) را باز کنید؛ اگر خطای 500 دیدید، بلوک را بردارید (معمولاً به این معنی است که `mod_headers` روی سرور نیست).
2. در DevTools → Network روی یک فایل CSS هدر `content-encoding: br` (اگر Brotli فعال است) و روی یک فایل woff2 هدر `cache-control: ... immutable` را ببینید.
