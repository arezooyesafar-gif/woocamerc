# راهنمای نصب روی هاست (مرحله ۵)

## فایل‌هایی که باید روی هاست قرار بگیرند
فقط این‌ها (همه داخل `public_html/wp-content/mu-plugins/`):
```
wp-content/mu-plugins/
├── tarh99-performance-loader.php
└── tarh99-performance/
    ├── tarh99-performance.php
    ├── index.php
    ├── assets/index.php
    ├── assets/fonts/ (۵ فونت آیکن سبک + manifest.json)
    ├── includes/  (۹ فایل)
    └── modules/   (۲۴ ماژول)
```
فایل `elementor-safe-mode.php` که الان در `mu-plugins` هست دست نمی‌خورد.

بسته آماده: `tarh99-performance-upload.zip` — محتوای آن را مستقیم داخل `wp-content/mu-plugins/` استخراج کنید.

## قبل از نصب
1. بکاپ کامل (فایل‌ها + دیتابیس) از cPanel → JetBackup یا Backup.
2. ترجیحاً ساعت کم‌ترافیک.
3. `docs/hosting.md` بند ۰ (ionCube) را خوانده باشید.

## نصب
1. cPanel → File Manager → `public_html/wp-content/`.
2. اگر پوشه `mu-plugins` وجود دارد (دارد)، واردش شوید.
3. Upload → فایل `tarh99-performance-upload.zip` → روی آن راست‌کلیک → Extract → مسیر همان `public_html/wp-content/mu-plugins/`.
4. بعد از استخراج باید `tarh99-performance-loader.php` و پوشه `tarh99-performance` کنار `elementor-safe-mode.php` باشند. فایل zip را حذف کنید.
5. پیشخوان → افزونه‌ها → تب **«ضروری» (Must-Use)**: «Tarh99 Performance» باید دیده شود. (افزونه‌های mu نیاز به فعال‌سازی ندارند.)
6. منوی جدید **«سرعت طرح۹۹»** در پیشخوان → تب ماژول‌ها → بدون تغییر، یک‌بار «ذخیره تنظیمات و پاک‌کردن کش» را بزنید (کش WP Rocket هم پاک می‌شود).

## چک‌لیست تست بعد از نصب (حالت مهمان، پنجره ناشناس، موبایل و دسکتاپ)
- [ ] صفحه اصلی: ظاهر، اسلایدرها، منو، حالت تاریک
- [ ] یک دسته‌بندی: کارت‌ها، فیلتر پیشرفته، صفحه‌بندی
- [ ] یک محصول: گالری، قیمت، افزودن به سبد، محصولات مرتبط، اسلایدر Wooslider، نمایش اشتراک
- [ ] جستجوی زنده هدر: چند کلمه فارسی، یک SKU، فیلتر دسته (دفعه دوم همان جستجو باید تقریباً فوری باشد)
- [ ] نمایش سریع محصول
- [ ] سبد خرید و شمارنده سبد هدر
- [ ] تسویه حساب و پرداخت زرین‌پال (یک سفارش تست یا حالت sandbox) و تکمیل خودکار سفارش
- [ ] ورود/ثبت‌نام پیامکی، حساب کاربری، پنل uPanel، دانلودها و اشتراک‌ها
- [ ] پیشخوان: داشبورد، لیست محصولات، ویرایش محصول، سفارش‌ها، تنظیمات ووکامرس، کوپن‌ها

اگر مشکلی دیدید:
- برای مقایسه سریع (فقط مدیر لاگین‌شده): به آخر آدرس صفحه `?tarh99_perf=off` اضافه کنید؛ صفحه بدون ماژول‌های فرانت نمایش داده می‌شود.
- ماژول مشکوک را در صفحه تنظیمات خاموش کنید.

## غیرفعال‌سازی فوری (اگر پیشخوان هم باز نشد)
یکی از این‌ها کافی است:
- File Manager → نام `tarh99-performance-loader.php` را به `tarh99-performance-loader.php.off` تغییر دهید. (وردپرس فقط فایل‌های `.php` ریشه mu-plugins را لود می‌کند.)
- یا در `wp-config.php` (خودتان) اضافه کنید: `define( 'TARH99_PERF_DISABLE', true );`
- حالت ایمن (همه ماژول‌ها خاموش، صفحه تنظیمات باز): `define( 'TARH99_PERF_SAFE_MODE', true );`
- خاموش/روشن کردن یک ماژول با ثابت (بر تنظیمات پیشخوان اولویت دارد): `define( 'TARH99_PERF_MODULE_SEARCH', false );` — نام ماژول همان شناسه انگلیسی کنار عنوان هر ماژول است.

## بعد از اطمینان از سالم بودن سایت (۲–۳ روز بعد)
1. **افزونه قدیمی Tarh99 Performance Suite را غیرفعال کنید** (حذف نکنید تا یک هفته). کارهایش (اولویت تصویر محصول، حذف lazy قالب، ایموجی، dashicons، Font Awesome تکراری، CSS محصولات مرتبط، sizes کارت‌ها) خودکار به افزونه جدید منتقل می‌شود. اندازه تصویر `tps_card_420` هم برای آپلودهای جدید ادامه پیدا می‌کند. فقط ابزار «ساخت تصویر کم‌حجم» برای تصاویر قدیمی منتقل نشده؛ اگر هنوز لازم است، قبل از غیرفعال‌سازی اجرایش کنید.
2. تنظیمات WP Rocket طبق `docs/wp-rocket-settings.md` (مرحله‌ای، با تست بعد از هر بخش).
3. بلوک `.htaccess` طبق `docs/htaccess.md`.
4. کوئری‌های `db-audit.sql` را طبق `docs/database.md` اجرا و نتیجه را بفرستید؛ سپس `db-cleanup.sql` (فقط بعد از بکاپ).
5. تنظیمات هاست طبق `docs/hosting.md` (OPcache، Redis، کران واقعی، PHP بعد از تست).
6. تصاویر طبق `docs/images.md` و وارد کردن نام فایل LCP صفحه اصلی در ماژول `lcp`.
7. حذف موارد اضافی (بعد از بکاپ):
   - `wp-content/plugins/Addons`، `Help`، `Plugin`، `Yoast`، `__MACOSX`، `2- Documentation`، `Help.pdf`
   - `wp-content/plugin/` (پوشه اشتباه با نسخه قدیمی RTL-CareUnit)
   - `wp-content/wflogs` و فایل‌های خالی `wp-content/temp-write-test-*`
   - نام پوشه `wp-schema-pro - 10` را دست نزنید مگر طبق راهنمای راست‌چین (تغییر نام = غیرفعال شدن افزونه).
8. اگر قالب پوشه را آپدیت کردید: ماژول «محافظ تغییرات دستی قالب» تغییرات functions.php (تکمیل خودکار سفارش، breadcrumb، حذف پیام دانلود) را خودکار برمی‌گرداند؛ با این حال بعد از آپدیت یک سفارش تست بزنید.
